# Finathink 用户自备数据接口范围补充

**日期：** 2026-10-06（Asia/Shanghai）
**状态：** 记录用户明确补充的范围；接口设计和实施细节仍为计划草案，不表示代码已经实现。

## 用户明确的产品责任

Finathink 是数据处理与研究平台，不是数据供应商。数据来源由用户选择，用户使用自己的 API Key 接入。平台只需要提供接口，不替用户寻找、购买、注册、下载市场数据或接通指定供应商。

此补充在数据接入范围上优先于旧设计中的指定供应商研究/接通任务。旧文件作为历史记录保留，不能据此重新扩张任务范围。

## 双方职责

| 用户负责 | Finathink 负责 |
| --- | --- |
| 选择数据来源和服务套餐 | 提供供应商无关的 API 接入接口 |
| 提供接口地址、认证信息和访问权限 | 安全接收配置，分离保存密钥 |
| 说明响应字段与数据含义 | 字段映射、标准化、清洗与分析 |
| 使用自己的数据服务账号和 API Key | 超时、重试、分页、额度与错误状态展示 |
| 决定接入哪个来源 | 数据快照、质量提示与后续研究产物 |

## 建议接口流程

用户填写连接配置和自己的 API Key → 平台连接器请求用户指定接口 → 字段映射 → 统一数据记录 → 清洗/分析/因子/回测/报告。

模型接口与数据接口使用独立配置和凭证引用。模型负责研究，不自行改变数据来源或读取密钥。

## 仍须保留的接口检查

- 校验响应格式、字段类型、缺失值、重复记录、时间戳与响应大小。这些是数据处理责任，不是审核数据商。
- 用户提供的来源名称只作为声明的元信息保存；平台不因此声称数据已核验、完整、正确或具有特定授权。
- 缺少发布时间、可用时间或修订时间时保持 UNKNOWN；缺失信息不能由 AI 编造，依赖这些信息的历史回测必须明确受限。
- API Key 不回显，不进入日志、模型输入、报告或 checkpoint。
- 仅请求用户配置的目标，避免越权网络访问、跨来源密钥泄露与无界下载。

## 首期范围与验收

首期做可配置的 JSON API 连接器、认证方式、字段映射、连接试测与清晰错误状态，不承诺所有 API 都能零配置接入；其他协议通过同一连接器合同扩展。

验收使用本地 mock API 和固定数据，不要求真实供应商、真实密钥、付费数据或行情下载。指定供应商连接不属于本计划的完成条件。
